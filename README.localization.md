# Git for Windows Localization Custom Build

This repository is a **locally customized** branch `localization/all-languages` based on
`git-for-windows/build-extra`, used to build a fully localized ARM64 (aarch64) Git installer.
**No upstream PRs are submitted** (upstream intentionally keeps the installer/translation files
lean; see dscho's remarks in git-for-windows/git#724 and #5353).

## Customizations (differences from upstream)

### 1. `installer/release.sh` - enable `WITH_L10N`
Pass `WITH_L10N=1` when invoking `make-file-list.sh`, so git core's gettext translations
(`clangarm64/share/locale/*/LC_MESSAGES/git.mo`, all translated languages) are no longer
filtered out by `make-file-list.sh`'s L10N gate.
Upstream does not pass this variable by default (the installer ships no locale files).

### 2. `make-file-list.sh` - allow-list man pages
- Add `man-db groff gcc-libs` to the package list (`man`/`mandb` commands and the groff
  typesetting tools, required for man rendering; `gcc-libs` provides `msys-stdc++-6.dll`,
  which groff's C++ components `preconv`/`tbl`/`groff` depend on).
- Change the unconditional filter `-e '/man/'` (substring match, excludes all man pages) to
  `-e '^/usr/man/' -e '^/usr/.*/man/'` (only excludes MSYS-side man pages), so that
  `clangarm64/share/man/**` (English + man pages for all translated languages) enters the installer.
- Remove `stdc++` from the filter regex
  `^/usr/bin/msys-\(db\|curl\|icu\|gfortran\|stdc++\|quadmath\)[^/]*\.dll$`
  (upstream deliberately excludes the large gcc runtime DLLs to save space, but groff depends on
  `msys-stdc++-6.dll`; without it `man git` outputs 0 bytes/blank).

### 3. `keep-despite-upgrade.txt` - non-package-owned file list
Lists custom files shipped with the package (they belong to no pacman package, so `pacman -Ql` does not list them):
- `/clangarm64/share/man/**` - git man pages for all translated languages + English git man pages
- `/clangarm64/share/man/zh_CN/**`, `/clangarm64/share/man/zh_TW/**` -
  standard locale directory names (man-db looks up `zh_CN`/`zh_TW` by `LANG`; the l10n project's
  `zh_HANS-CN`/`zh_HANT` names do not match and need mapping)
- `/usr/bin/col.exe` - `col`, needed by the man output pipeline (belongs to the excluded util-linux package)
- `/clangarm64/share/doc/git-doc/<lang>/**` - git HTML docs for all translated languages
  (git help's html mode points to a language directory via `help.htmlpath`, e.g. Chinese `zh_CN/`)

## Localization source and build

### Git core messages (all translated languages)
`git/git` ships its own `po/` (gettext); `make install` generates
`clangarm64/share/locale/<lang>/LC_MESSAGES/git.mo` at build time.
Languages: bg ca de el es fr ga id is it ko pl pt_PT ru sv tr uk vi zh_CN zh_TW.
Takes effect via `LANG`/`LC_ALL` (test: `LANG=zh_CN.UTF-8 git status` -> Chinese error messages).

### Git man pages (all translated languages + English fallback)
- Translation source: the official doc translation project `jnavila/git-manpages-l10n`
  (aligned to the Git for Windows version currently being built).
- Build: `make man` (po4a v0.74 translation -> asciidoctor renders `.1/.5/.7`).
  There is a per-page >=80% translation threshold (`pre-translate-po`): complete languages
  (fr/ru/uk/sv/zh_HANS-CN/pt_BR and partly de/es/ja) produce 116-151 pages; skeleton languages
  (15-39% complete) have most pages dropped -> 0 pages, fall back to English.
- Installed to `clangarm64/share/man/<lang>/man{1,5,7}`.
- English fallback: generated by git source `Documentation/make man`, installed to
  `clangarm64/share/man/man{1,5,7}`.
- Simplified Chinese mapping `zh_HANS-CN->zh_CN`, Traditional `zh_HANT->zh_TW` (needed by man-db locale lookup).
- How it takes effect (without changing help's default html behavior):
  1. User runs `git config --global help.format man`
  2. Git Bash's `profile.d/lang.sh` sets `LANG` automatically from the Windows user locale (`locale -uU`)
  3. `man`/`groff`/`less` ship with the package; MANPATH includes `clangarm64/share/man`
  -> verify: `LANG=zh_CN.UTF-8 man git` shows the Chinese man page.

### Git HTML docs (all translated languages)
- Same source as man pages: the same `make html` generates xhtml5 from translated adoc (`asciidoctor -b xhtml5`).
- Installed to `clangarm64/share/doc/git-doc/<lang>/` (same directory as official English html, per-language subdirs).
- Simplified/Traditional mapping as above: `zh_HANS-CN->zh_CN`, `zh_HANT->zh_TW`.
- **git help's html mode does NOT look up by locale automatically** (`builtin/help.c` only opens
  `htmldir/<page>.html`); the user must configure a language directory:
  `git config --global help.htmlpath "<install-dir>\clangarm64\share\doc\git-doc\<lang>"`
  (for the `<lang>` directory names, see [git-manpages-l10n README](https://github.com/jnavila/git-manpages-l10n/blob/master/README.md));
  after that `git help git` (`help.format=html`) opens the docs for that language in a browser.
- Complete languages have about 150 pages per language (fr/ru/uk/sv/zh_HANS-CN/pt_BR etc.);
  skeleton languages are missing pages (same threshold as man pages); for incomplete languages it is
  recommended to point at a complete directory such as `zh_CN`, with English pages as fallback.
